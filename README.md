# Scrap Tycoon

Idle game thu gom phế liệu theo **chuỗi logistics 6 công đoạn**: nhặt ve chai → bốc vác →
xưởng tái chế (rèn) → ba gác → nơi đóng hàng → xe tải xuất — mỗi chặng có nhân lực riêng,
kho có sức chứa nên chặng sau chậm là chặng trước nghẽn. Nhánh "Đồng nát" là walking skeleton;
các nhánh tiếp theo (Điện tử → Xe cộ → Xe hơi, chi nhánh...) chỉ cần **thêm content/data**,
không sửa engine.

Bên cạnh dây chuyền idle, bạn **tự đi trong bãi**: WASD để đi (Shift chạy nhanh, M mở bản đồ),
đứng trong khu rồi **giữ F** để làm việc bằng tay — chọt lon, vác bao, đập đe, đóng kiện. Việc tay
là event, không phải rate, và **gom hàng vào túi của bạn**; bấm **E** mở túi đồ kiểu game sinh tồn
(lưới ô, icon từng loại hàng) rồi đứng ở khu sở hữu hàng đó mà bỏ vào kho — hàng trong túi chưa nằm
trong dây chuyền cho tới lúc đó.

Quy tắc code bắt buộc cho mọi contributor/AI agent: xem [AGENTS.md](./AGENTS.md).

## Kiến trúc

```
src/
  core/      # engine game-agnostic: Decimal (break_eternity), format số, clock, store, save + migrations
  i18n/      # type L10n (VI/EN compile-time), locale store, UI strings
  domain/    # luật chơi THUẦN: modifiers, production/legs/recipes, capacity, offline, commands, selectors
  content/   # toàn bộ balance là DATA: items, branches/, upgrades, curves — chỉ app + tests import
  ground/    # kit nền: engine ở ground/core, dự án bind qua ground/packs/<id>
  scenery/   # kit ánh sáng/khói/chim + hai tầng LOD props (scenery/core + packs)
  scene/     # kit runtime 2D: camera, LOD, culling, layer + hợp đồng ScenePack (scene/core)
  ui/        # HUD React + adapter scene của game (chỉ ĐỌC state, không mutate)
  platform/  # StoragePort adapters (localStorage / memory)
  app/       # composition root: bootstrap, engine (EngineApi), loop (ticks + autosave + offline)
```

Ranh giới layer được **enforce tự động** bằng dependency-cruiser (`.dependency-cruiser.cjs`):

- `core` không import gì của repo; `domain` chỉ `core` + `i18n`; `ui` không được import `content`/`app`.
- `ground/core`, `scenery/core`, `scene/core` là **kit nhấc ra được**: không import pack/dự án/`content`/`ui`; phần bind một dự án nằm ở `*/packs/<id>`. `scene/core` giữ runtime (camera nấc zoom nguyên, LOD 3 tầng, culling theo view, thứ tự layer) và nhận một **`SceneFeed`** (số + chuỗi đã dịch) do dự án đẩy vào — runtime **không biết `domain`**.
- `content` được inject từ `app` qua React context (`useContent()`) — UI render data-driven.
- `core`/`domain`/`i18n`/`content` cấm import `react`/`pixi.js`.
- Thêm import sai tầng → `npm run depcheck` fail ngay.

Các pattern trục chính:

- **Modifier pipeline**: `final = (base + Σflat) × Πmult × Πglobal` — mọi upgrade/prestige/bonus đổ vào đây qua `statKeys`.
- **Nhân vật + việc tay + túi đồ + trang bị**: `ScenePack.makePlayer` cấp một `WorldLayer` — nhân vật ở `ui/scene/player/` (`walkable.ts` là nguồn duy nhất cho "chỗ nào đứng được": rào khu + lỗ mở, ao theo đúng `blobContour` đã vẽ, gò cao, đế của decor `solid`; `keys.ts` giữ phím trong một ref, không setState). Đứng trong khu thì **thân nhân vật được reparent vào lớp `actors` của khu** nên khu tự y-sort cho nó đi sau chồng kho/lò; camera theo nhân vật (`setFollow`), kéo chuột thì tạm ngắt, nút **"Về nhân vật"** quay lại. Việc tay là **command** (`performAction`) + data ở `content/actions.ts`; **một nhát đổ hàng vào TÚI** (`GameState.bag`, trần riêng từng loại ở `ItemDef.carry`) và rút nguyên liệu từ túi trước rồi mới tới kho khu. HUD giữ đồng hồ **giữ-F** và thanh tiến trình (`ui/hud/ActionBar.tsx`), **E mở modal hai tab** — **"Túi đồ"** (`ui/hud/InventoryPanel.tsx`, lưới ô + icon pixel vẽ bằng code ở `ui/itemIcons.ts`) và **"Nhân vật"** (trang bị) — scene chỉ diễn hoạt ảnh (`focus/poses.ts` dùng chung với thợ) — mở modal thì nhân vật đứng yên (`freezeWalk`). Tab Nhân vật là khối trang bị (nón · áo · quần · dép · đang cầm): mua bằng tiền (`content/gear.ts`), mặc luôn và **thấy trên người** (`createPersonSprite` nhận `BodyStyle`; scene dựng lại thân khi look đổi), chỉ số đi qua modifier pipeline (`global.carry` / `player.workSpeed` / `player.walkSpeed`). Túi và trang bị là state **có** trong save ⇒ schema v4 (migration `2 → 3` tạo túi rỗng, `3 → 4` tạo bộ đồ rỗng).
- **Command → State → Event(store) → UI**: UI chỉ đọc state qua selectors + `useSyncExternalStore`; mọi thay đổi đi qua `domain/commands` hoặc `domain/tick`.
- **Camera thủ công + 3 tầng LOD pixel**: zoom tay qua 3 nấc nguyên 1×/2×/4× (con lăn chuột hoặc nút trong scene), giữ chuột kéo để pan giữa các khu; hover card = highlight khu, bấm card = camera tới khu; nút **"Bản đồ"** (hoặc phím **M**) mở **minimap sơ đồ** — vẽ từ chính dữ liệu layout (khu/bãi/ao/đường) + khung vùng nhìn, bấm lên đó là camera bay tới. **Canvas = viewport, không phải thế giới**: `ScenePack.viewport` khai cỡ canvas (1280×720) và thế giới 10240×5760 được vẽ theo **chunk lazy** — `scene/core/chunks.ts` bake từng chunk 512² ra texture và chỉ giữ chunk quanh vùng nhìn, `paintGrounds(..., window)` cắt **mọi** pass theo window (kể cả decor: `map.decor(decor, window)`, nếu không mỗi chunk phải vẽ cả ~850 món của thế giới); LOD props theo bucket, đèn/khói/chim/ao/mưa/mây đều cull theo `view` truyền mỗi frame. Art ở **độ phân giải gấp đôi** (tile 16px, người ~30px, cây ~48px, hoa 4–5px) vẽ **1:1** lên canvas (`CANVAS_SCALE = 1`) và hiển thị theo chế độ **vừa khung** (fractional scale, <1× thì tự chuyển smooth để khỏi rơi pixel). Độ chi tiết tăng theo nấc zoom: 1× = art zone đầy đủ (lưới 1px, trong `ui/scene/focus/`), 2× = thêm **micro props** (lưới 0.5px, `SceneryPack.microProps`), 4× = thêm **nano specks** (lưới 0.25px, `SceneryPack.nanoProps`). Mỗi khu là một folder cùng cấu trúc 3 file như pattern chung: `focus/<zone>/sprites.ts` (art) / `actors.ts` (animation state machine) / `scene.ts` (props + lắp ráp); đồ dùng chung ở `focus/parts.ts`.
- **Thế giới = lõi công việc + hoang dã (10240×5760)**: **đại lộ** asphalt chạy hết chiều ngang map (khu `route` là một đoạn của nó), **lõi** ~2600×1000 giữ 5 khu dây chuyền đúng cỡ authored (đi bộ giữa các chặng vài chục giây), quanh lõi là **bãi khai thác** (3 bãi phế liệu, mỏ sỏi nhô, nền rừng — chỗ để làm việc bằng tay), phần còn lại là rừng vành, cụm rừng, hồ tây, ao, gò cao và bãi đất. Tất cả là **data** ở `worldLayout.ts`/`worldGrounds.ts`; `tests/layout.test.ts` khoá bất biến (khu không chồng, ao không đè khu/đường/đại lộ, làn ↔ lỗ mở rào, lõi gọn, decor không đè đường/ao, decor phủ cả hoang dã).
- **Kit scenery dùng lại được (`src/scenery/`)**: `scenery/core` giữ grade ngày/đêm + quầng đèn (`createLighting`), khói/chim (`createAmbience`) và hai tầng LOD props (`createDetailLayer`); mỗi dự án khai một `SceneryPack` (đèn, smoke/bird spec, danh sách prop + drawer) — không import qua lại. Khói ống khói, đèn đường, specks giờ là **dữ liệu pack**, không còn hardcode trong layer — và hai tầng LOD props **phủ toàn map** (thêm lượt rải ngoài khu, trừ ao), không dừng ở ranh khu nữa. Ambience có 3 lớp: khói (4 nguồn), chim trời, và **chim đậu mổ đất** mỗi con bám một tổ (không đi lạc, thỉnh thoảng bay một vòng).
- **Kit nền là thư viện dùng lại được (`src/ground/`)**: engine ở `ground/core` (contour, trường tông/mật độ, `TilePainter` + `paintGrounds`, autotile 16 case, wall bands) **không import gì của dự án** — depcruise `ground-core-is-self-contained` enforce; mỗi dự án là một **pack** ở `ground/packs/<id>` khai terrain (palette ramp sáng ≤ 10/255, tones, kiểu vẽ ô, salt), specimen scatter, decal, bờ nước và **map** (làn/sàn/mảng/vết/đường nối/ao + seed) — game chỉ gọi `new TilePainter(renderer, pack)` + `paintGrounds(...)`. `packs/meadow` là pack demo chứng minh điều đó; `tests/groundPack.test.ts` validate cả hai. Studio tab **"Pack nền"** là hub đa dự án: chọn pack → xem bảng tile và map của pack (vẽ bằng chính đường game đi) kèm kết quả validate.
- **Kit scene dùng lại được (`src/scene/`)**: `scene/core` là runtime dùng chung — camera nấc zoom nguyên + kéo pan neo theo con trỏ, CSS fit, LOD 3 tầng, culling theo view, thứ tự layer, và `SceneHandle` (`setFeed`/`setZoomLevel`/`panTo`/`setHighlight`/`focusOn`/`setFollow`) — nhưng **không import `domain`/`i18n`/`content`/`ui`**: dự án đẩy vào một **`SceneFeed`** (số + chuỗi đã dịch) qua adapter `ui/scene/{feed,PixiScene}.ts`. Mỗi dự án khai một **`ScenePack`** (world + viewport + zone rects/`color`, ground pack & hàm paint, scenery pack, registry scene chi tiết, tuyến courier, thời tiết) — hiện của scrap ở `ui/scene/scrapPack.ts`. `Wind`/`CALM_WIND` sống ở `scenery/core/ambience` (**một bản duy nhất**). **Nước động**: `ScenePack.water` cấp contour ao + tông sóng (base nước pha ~50% về highlight của chính nó), kit dựng `createWaterLife` — **sóng đánh thành đợt**: mỗi ao 3 đường mào sóng, dash cắt theo `chordsAt` (lấy mọi đoạn nước của hàng, không bao giờ vẽ lên gò khô), **sóng sánh giữa hai bờ** (dội bờ rồi quay lại, flip cả độ nghiêng), **nghiêng mỗi đường một hướng** (`slope`) và **lượn lên xuống dọc chiều dài** (`crestLift`), mỗi dash tự cắt theo hàng của chính nó nên không bao giờ hở ra bờ, `swellStrength` cho chu kỳ ~9s nên sóng đến theo cụm; **cá bơi dưới mặt** (`WaterLayer.fish`, 1–4 con/ao, tự kiểm tra hai đầu thân còn trong nước); chèn theo thứ tự ground → water → decor. Test: `tests/scenePack.test.ts`.
- **Tileset generate bằng code (tái sử dụng)**: `src/ground/packs/scrapYard/tileSet.ts` sinh texture cho grass/dirt/water/gravel/asphalt/concrete (đất 8 biến thể, nước 6, sỏi 6, còn lại 4 — nền không phẳng một màu, cộng 3 **tile fringe** chỉnh tay); `TilePainter` (`src/ground/core/painter.ts`) với `paint` (vùng thẳng), `paintMasked` (đường/slab), `paintBlob` (mảng cong hữu cơ — mép giải theo **autotile 4-góc 16 case** bằng bộ **tile chuyển tiếp** sinh riêng ở `src/ground/core/edgeTiles.ts`: môi cỏ + viền tối ambient-occlusion + tông nền, mẫu góc jitter theo hash vị trí nên đường viền khớp giữa các ô và không bao giờ vỡ; bên trong mảng có mảng tông lớn + rác dọc mép + cỏ mọc lấn), `patchwork` (mảng sáng/tối lớn cho cỏ) và `scatter` **2 lớp** (`flora`: hoa cúc/vàng/hồng/xanh, cụm cỏ rậm, nấm, bụi nhỏ — vẽ trước blob để chỉ nằm trên cỏ; `debris`: sỏi, cành khô, lá rụng, đá, vết nứt — vẽ sau, có cả trên đất). Cả bản đồ được lắp ở `src/ground/packs/scrapYard/worldGrounds.ts` (`paintWorldGrounds`) nên game và studio vẽ từ đúng một nguồn. Thêm khu/đường mới chỉ cần gọi paint, không vẽ nền tay.
- **Hệ chuyển tiếp là CẶP (trong, ngoài)** — `src/ground/packs/scrapYard/terrains.ts` là nguồn duy nhất cho: danh sách terrain (`PRIMARY_TERRAINS` là mặt nền người chơi thấy), bảng tông (`EDGE_TONES`), và **`TERRAIN_PAIRS`** — danh sách **cặp có thật trên map**: đất↔cỏ, nước↔cỏ, **nước↔đất (vũng bùn)**, sỏi↔cỏ, sỏi↔đất (bãi sỏi đào trong mảng đất), bê tông↔đất (sân trước kho). **KHÔNG có cặp cùng nền trong danh sách**: sàn khu nằm trong bãi cùng loại nền thì `paintTiles` **bỏ hẳn tile chuyển tiếp** (chỉ lát tile thường + trang trí bên trong) — nếu không, vành môi + quầng AO sẽ vẽ một đường khoanh vô nghĩa giữa hai vùng **cùng một vật liệu**, đúng cái làm sàn khu trông "dán" lên nền. Test `tests/terrain.test.ts` khoá lại (`has('dirt','dirt') === false`). Mỗi cặp sinh đủ 16 case autotile × 2 biến thể, **môi ngoài lấy tông của chính nền ngoài**. Studio có **2 dropdown Trong / Ngoài + nút ⇄ đảo** (36 tổ hợp, kể cả cặp cùng nền).
- **Rác dọc mép**: `fringeInside` (bước 4px) rải **cụm cỏ 2–3 lá mọc lấn vào trong (85%)**, **cụm cỏ mọc hẳn RA NGOÀI mép (50%)**, **vụn nền trong rơi ra ngoài (30%)**, **sỏi/đá 3 cỡ** (1px / 2px có đỉnh sáng + bóng dưới / 3×2 có bóng tiếp xúc — 45%), **cục đất vụn 2–3px (30%)** và **cỏ dại 2–3 lá (35%)** — tất cả bám sát contour nên phá mọi đoạn thẳng mà lưới ô tạo ra, mà không sinh vết cắn vào mép. Lớp `scatter('debris')` phủ thêm sỏi/cành/lá toàn map (cắt theo mật độ trường), nên chỗ nối nào cũng có rác vương.
- **Chỗ nối = ramp loe, `outside` phải là nền THẬT xung quanh**: tile chuyển tiếp kéo theo **một vành rộng 1 ô theo đúng tông của `outside`** — `outside: 'asphalt'` giữa đồng cỏ sinh ra "cái nêm xám" làm bản đồ rối nùi (đã bị bỏ); vành chỉ vô hình khi nó rơi lên chính loại nền đó (hoặc cùng tông). `paintPath(rect, kind, seed, outside, flare, ramp, mouths, jitter)` + `rectContour(rect, flare, ramp, mouths, jitter)` với `mouths: 'top' | 'bottom' | 'both'`. **Làn ĐẤT phải truyền `jitter > 0`** (wobble hai bên dài ±5px, ghim cuống/miệng): mép tuyệt đối thẳng không bao giờ bước theo lưới ô (corner sampler chỉ ±3px, dưới nửa ô) nên render ra đường kẻ thước + hàng tile mép đồng nhất — đọc thành "hình chữ nhật dán" (đã bị báo ở làn alley→recycle); đường nhựa/bê tông giữ `jitter = 0` cho mép thẳng. **(b)** lối vào nhà khu **dưới-trái** = ramp môi ĐẤT (nằm trong bãi đất của kho), **(c)** hai lối vào sân công nghiệp = ramp môi SỎI (nằm trong bãi sỏi của sân) — vẽ trong `worldGrounds.ts`; **ĐỪNG vẽ mảng đất/sỏi lên trên mặt nhựa** — vành 1 ô của tile chuyển tiếp hiện thành viền sáng quanh mảng và đọc ra "vết bẩn có outline" (đã thử ở `focus/route/scene.ts` rồi bỏ); mép đường cứ để thẳng vì đường trong pixel art vốn thẳng. **(a)** làn đất khu ve chai→đường **rộng 72px đều**, loe 44 ở **đầu bãi** (`mouths: 'top'` — đầu gặp đường mà loe là ra hình thang lộ liễu) và **kết thúc đúng mép đường** (asphalt của khu `route` vẽ sau nên phủ mất phần vành vươn lên mặt đường). Sân bê tông trước kho và làn nhựa trong sân đổi từ `paintMasked` (cạnh thẳng + viền) sang `paintPath` có môi đất — **đừng quay lại slab vuông**. Bờ nước (`waterDetail.ts`) có thêm **đất bờ bị xói** (vệt bùn + cục đất sạt + sỏi ướt dính cụm). **Tường bậc cao** (`src/ground/core/wallBands.ts`) vẫn vẽ theo đa giác: nam/đông có gờ sáng + mặt tường + chân gạch đứt + bóng đổ, bắc/tây chỉ gờ sáng. 
- **Viền mảng = AMORPHOUS lởm chởm theo lưới tile**: `blobContour` (`src/ground/core/edgeGeometry.ts`) gồm **4–5 thuỳ sin**: hai thuỳ tần số 1–2 (3–5%) đẩy hẳn hai phía ra — thứ phá cảm giác "elip"; 2–3 thuỳ tần số 3–6 (2–4%) làm phình/lõm không đều dọc viền; cộng **nhiễu xuyên tâm mỗi mẫu**: `CONTOUR_JITTER` = **7px** (`min(7, r·0,12)`) — **đây mới là thứ xoá các đoạn thẳng dài**: lưới 16px chỉ ngừng cắt một đường phẳng khi contour lệch ~1 ô trong ~2 ô chiều dài, nên phải gợn ở **quy mô 1 ô**, không phải 4px (jitter 4px để lại đoạn phẳng 3–4 ô → ao bị đọc thành "hộp"). Ngân sách sóng **chuẩn hoá**: `CONTOUR_AMP` = 8,5% bán kính, sàn tuyệt đối `CONTOUR_MIN_AMP` = 12px, **chặn trên 22%** bán kính (chỉ tính % thì ao nhỏ ra hình chữ nhật bo góc; chỉ có sàn px thì ao 70×44 méo 30%). Đo thật: ao phải (880,120) lệch **12,3px / 32 lần phình-lõm**, ao nhỏ (700,610) 7,3px / 31 lần. Test `tests/edgeTiles.test.ts` (`reads as an amorphous clearing, not an ellipse`) khoá cả 3: **≥ 12 lần phình/lõm**, độ gợn **sống sót qua làm mịn > 4px**, lệch tối đa **< 1,4 ô**. **Đừng quay lại mask đa giác + dải vẽ theo đa giác** (mép trơn như vector, mất chất lưới ô — người dùng gọi là "nhân tạo") và **đừng chỉ tăng biên độ** (ra amoeba).
- **Nước (ao) có đủ chuyển tiếp + rác trôi**: `water` là một `TileKind` bình thường nên có 6 tông xanh lục lam đục và dùng đúng bộ autotile để nối với nền ngoài — dải trong cùng là **bùn ướt ở mép nước**, dải ngoài là môi nền ngoài. Pass bờ riêng ở `src/ground/packs/scrapYard/shore.ts` — **cố tình thưa**: vành **bọt nước** mảnh men mép, sỏi ướt nửa chìm, sỏi khô trên bờ, thỉnh thoảng một lá súng (lau sậy đã bị gỡ vì làm ao trông um tùm). Lớp **scatter `water`** rải rác trôi trong mặt nước: 8 món "rác & nước" (váng dầu, lá, vỏ lon, bọt, cành khô, bèo, gợn sóng, chai) cộng **4 món thực vật** — **bông lục bình** (tím), **bèo tấm** (mảng hạt li ti), **hoa sen** và **lá súng nổi**; vùng nước lặng (mix cao) nghiêng hẳn về thực vật, vùng nước bẩn nghiêng về dầu/lon/chai, hoa vẫn rải lác đác ở vùng trung tính. Toàn bộ bị **cắt theo đa giác ao** nên không bao giờ trôi lên bờ, và cũng theo trường mật độ như các lớp khác. Bản thân các specimen (flora/debris/water) nằm ở `src/ground/packs/scrapYard/specimens.ts` — module thuần, vẽ qua `GroundCanvas` nên test được toạ độ bằng stub. **5 ao** khai báo ở `worldLayout.WATER_AREAS` (lớn nhất 170×100) — trong đó **vũng bùn (440,500) nằm trọn trong mảng đất `CLEARINGS` nên cả bờ là bùn** (demo cho cặp nước ↔ đất); nước cũng đi qua trường chọn biến thể + xoay/lật ô như các nền khác. Map rộng **1280×720**: 4 khu giữ nguyên cỡ nhưng dàn xa nhau, phần đất mới có thêm clearings, 2 đèn đường và 20 cây/16 bụi/8 gốc/6 đống sắt rải lại.
- **Mật độ chi tiết nền = THẤP (bài học "chưa ra dáng Stardew")**: nền pixel art đọc ra là **màu phẳng + vài chi tiết**, không phải "texture rải khắp". Vì vậy `tileSet.ts` vẽ **rất thưa**: cỏ/nhựa/bê tông **4 hạt/ô** (trước 16), đất/sỏi **3 hạt + 1 cụm 2–3 hạt + thỉnh thoảng 1 vệt xước + 1 viên sỏi** (trước ~20 mảnh), nước **2 gợn + 2 chấm sâu** (trước 3+4) — tức ~1 chi tiết mỗi 40–50px, không phải mỗi 10px; thêm chi tiết là **tăng vào cụm/palette** chứ không nhồi đốm rời. Ngưỡng rải rác trong `painter.scatter` cũng đẩy cao (sạch < 0,3 thay vì < 0,18; 1 món tới 0,7; 2 món tới 0,92) nên ~⅓ map sạch hẳn và rác tụ thành cụm rõ, thay vì "trường chấm bi" đều khắp map. Mảng tông bên trong mảng đất/cỏ cũng nhạt đi (`tonesInside`: α 0,07–0,05, bước 48px) để không thành các khối màu chồng nhau.
- **Đất/sỏi có texture thật, không phải nhiễu**: `tileSet.ts` vẽ đất **8 tông lệch hue** (sét ngả đỏ, tro ngả xám, cát ngả vàng, đất ẩm nâu sậm…), sỏi 6 tông; **thứ tự biến thể là ramp sáng** — trường tông lượng tử theo index nên hai biến thể kề nhau là hai dải cạnh nhau trên map, xếp hue lộn xộn sinh bước nhảy 18/255 ở biên dải và đọc thành "khối chữ nhật" (đã bị báo ở làn alley→recycle); test `tests/tileVariety.test.ts` khoá bước liền kề ≤ 10/255 cho mọi terrain. Mỗi ô là **hạt theo cụm** (2–4 hạt dính nhau) + vệt xước + một viên sỏi có đổ bóng (mặt sáng/đáy tối) + mảng ẩm.
- **Chống "nền caro" (`src/ground/core/variety.ts`)**: biến thể tile và tint **không** chọn theo từng ô (hash mỗi ô = bàn cờ ở cỡ 16px) mà lấy từ **trường nhiễu tần số thấp** — mảng tông 72px + trường chi tiết 40px làm rìa mảng gợn tự nhiên — nên các ô kề nhau chia cùng một tông thành mảng lớn. **Trường tông lấy mẫu trên lưới XOAY ~35°** (`TONE_SKEW_*`): value-noise biến thiên theo trục lưới của nó, nên một trường không xoay khi bị lượng tử hoá thành các dải tông sẽ vẽ ra **mảng chữ nhật** trên màn hình — đúng cái đọc thành "tileset không smooth"; xoay miền lấy mẫu là hết, không tốn gì. Cỏ có **6 tông chênh ≤ ±4% sáng** (trước 4 tông chênh ±8% → bước tông to, thành ô khác màu) và `BLEND_RANGE` = 0,45 nên rìa mảng tông được **dither** rộng. Thêm 3 lớp nữa: **xoay/lật ô** (chỉ cho nền đẳng hướng: đất/sỏi/nhựa/bê tông; cỏ và fringe không xoay vì lá phải hướng lên), **dither hạt ở rìa mảng tông** — dither **dồn về phía cạnh giáp ô khác tông rồi mờ dần vào trong** (`boundaryDitherWeight`), chứ không rải đều cả ô (rải đều biến mỗi ô biên thành một khối lốm đốm, và trên làn hẹp ranh giới chạy dọc thành chuỗi 9 ô lốm đốm liền — đã bị báo), và tint cũng theo trường (dao động ±3% theo mảng, chỉ còn ±1% nhiễu ô). Lưu ý kỹ thuật: mọi hàm hash ở đây dùng bản **có avalanche** (murmur3-style) — hash yếu kiểu `imul` + một xorshift làm input nguyên nhỏ gần như tuyến tính, biến nhiễu thành mặt phẳng (đúng lỗi đã gây ra nền caro).
- **Tỉ lệ scatter theo trường mật độ**: số món rải trên mỗi ô **không cố định** — `scatterDensity` (trường 64px trong `src/ground/core/variety.ts`) chia map thành **~22% sạch hẳn / ~66% thưa-vừa / ~12% dày** (0–3 món mỗi ô, mật độ trung bình 0.45), và `scatterMix` quyết định *loại* món theo từng vùng (một mảng hoa, mảng cỏ rậm; một bãi sỏi, một chỗ cành lá). `clustersInside` trong `paintBlob` dùng **cùng trường** nên chỗ sạch thì chỉ làm nhạt đất (không thêm rác) còn chỗ dày thì cụm sỏi tụ vào — hết cảnh tính trùng hai lần thành dày đều. Gió lan qua `setAmbient` cho cờ ở cổng, khói (ống khói/thùng phuy/ống xả) và chim/hải âu.
- **Mở khoá theo chuỗi + mốc tiến trình (derived — không đổi save)**: content khai `requires` (kiểu `Condition`) trên zone/branch/worker/upgrade — nhánh đồng nát khoá khu theo thứ tự dây chuyền (xưởng cần bốc vác ≥ 1, tuyến cần thợ rèn ≥ 1, kho cần ba gác ≥ 1, cổng cần thợ đóng hàng ≥ 1) và gate upgrade theo chặng (bễ/bàn đóng kiện… cần thợ chặng đó, `box-truck` cần `pickup`). `domain/conditions.ts` eval THUẦN từ state, `domain/commands.ts` chặn mua bằng reason `locked`; điều kiện **đơn điệu tăng** (số thợ/tổng tiền/thời gian chơi) nên save cũ không bao giờ bị khoá lại và **không cần field nào trong save**. `content/milestones.ts` khai 8 mốc (số thợ / tổng tiền / thời gian chơi) thưởng **hệ số vĩnh viễn** chảy qua `collectModifiers` (cùng đường với thời tiết — tick/offline/selectors thấy như nhau); engine phát hiện mốc mới bằng diff in-memory (`newlyCompletedMilestones`) rồi đẩy qua `setMilestoneHandler` → toast + âm "Đạt mốc"; panel "Mốc tiến trình" ở đầu sidebar, chip "Khoá" + dòng điều kiện trên card khu/thợ/upgrade (chữ dịch ở `ui/progression.ts`). Thêm khoá/mốc = sửa content, `validateContent` bắt ref lệch; thưởng mốc tính vào envelope golden nên **tune số trong content, đừng sửa assert**.
- **Chuỗi logistics + kho theo khu**: `content/branches/scrap.ts` khai 6 đơn vị, mỗi chặng một đơn vị `input → output` (`WorkerDef.input` — bốc vác, thợ rèn, ba gác, thợ đóng hàng, xe tải bán ra); `content/items.ts` khai **sức chứa** (`ItemDef.cap`) cho từng kho. **Kho là per-zone, không còn một pool chung**: `GameState.stock[zone][item]` giữ hàng từng khu, tiền (và item không thuộc khu nào) nằm ở `resources`; `domain/zones.ts` là nguồn duy nhất suy ra item ↔ khu (chặng tiêu thụ item là khu sở hữu bin đó — bốc vác rút từ bin đứng cạnh nó), `zoneStockItem`/HUD/scene đọc cùng nguồn đó. Ba pass trong `applyRates` chạy theo thứ tự **sản xuất → vận chuyển → recipe** và đọc/ghi **bucket của khu sở hữu item**: producer bị chặn bởi cap bin đích; leg tiêu thụ bị chặn bởi hàng tồn trong bin nguồn **và** headroom bin sau (không bao giờ mất hàng) rồi nhả theo tỉ lệ `output/input`; recipe vớt phần dư. Nhờ vậy chặng sau chậm → kho khu đó đầy → chặng trước dừng (ZoneCard hiện **mọi dòng kho của khu** + chip "Đầy", scene hiện bao/thùng đầy dần). Nâng sức chứa bằng upgrade target `item.<id>.capacity` (**đủ cả 5 bin**), và mỗi chặng có **upgrade tốc độ riêng** qua key `branch.<branch>.worker.<id>.output` (song song với key chung `branch.<branch>.workerOutput`); markup (`branchRecipeOutput`) **chỉ nhân đầu ra là tiền** nên không sinh vật liệu từ hư không. Mỗi chặng còn có **kênh bán lẻ phần dư** (recipe giá rẻ, throughput giới hạn) để luôn có thu nhập xây tiếp, còn tiền lớn nằm ở hợp đồng xe tải xuất.
- **Courier xuyên khu (`ui/scene/couriers.ts`, map-level)**: mỗi chặng vận chuyển có **tuyến chạy nhìn thấy được** giữa hai khu — `COURIER_RUNS` keyed theo **cặp khu** (`<from>><to>`, ui không key theo worker id): bao alley→recycle (đường đất), phôi recycle→route (làn nhựa xuống mặt đường), pallet route→depot (làn nam + driveway kho, **xe ba gác** đúng bậc fleet của khu xuất phát), kiện depot→gate (driveway + vỉa hè nam). Path là waypoint world-space **phải nằm trên nền đã vẽ** (test `tests/couriers.test.ts` khoá bằng union zone rects + `CONNECTORS` + đường đất alley→forge). Walker **vác hàng ở chiều đi, về tay không** (tiếng vác/thả + bụi), xe quay đầu ở hai đầu; **hàng được đặt xuống đúng chồng kho của khu đích** (`CourierRun.drop` — chồng bao ở xưởng, chồng phôi ngã ba làn, chồng pallet cổng kho, chồng kiện cổng xuất, mỗi chồng lớn dần theo tồn thật + dấu đỏ khi đầy). Số courier = số thợ sở hữu (có cap mỗi tuyến), cull theo view y như zone scene nên tiếng chỉ kêu khi nhìn thấy. Chặng truck không có tuyến — "giao" của nó là chạy khỏi map (animation xe tải sẵn có). Layer thuần trang trí: chỉ đọc count, không chạm domain; studio tab Thời tiết dựng đủ 4 tuyến để nghiệm thu.
- **Offline = cùng code path với online**: `applyOfflineProgress` dùng chung `computeProductionRates`/`applyRates`; content thuần tuyến tính (không cap/không leg/không thời tiết) thì **1 bước lớn là chính xác**, còn có cap/leg thì cắt chunk tại biên block thời tiết + `simulation.offlineChunkSeconds` (offline có cap là xấp xỉ có kiểm soát: online tick 0.1s, offline chunk 1s).
- **Save**: chỉ chứa state (ids + counts, Decimal dạng string), có `schemaVersion` + migrations; load xong prune id lạ / fill id thiếu nên content đổi không phá save cũ. Từ **v2** kho ghi thành section `stock` **phẳng theo item id** (không bake zone vào file — zone là suy diễn từ content, đổi item sang khu khác vẫn load đúng); migration `1 → 2` chuyển `resources` cũ sang `stock`, hydrate phân loại lại theo content (tiền về `resources`).

## Thêm nội dung mới (Phase 2+)

1. Tạo `src/content/branches/<tên>.ts` theo `BranchDef` (workers, recipes, upgrades).
2. Khai báo khu vực trong `src/content/zones.ts` (tên + mô tả hành động) và thêm layout tương ứng vào `src/ground/packs/scrapYard/worldLayout.ts` — mỗi worker trỏ tới 1 zone qua `visual.zone` + hành vi qua `visual.action` (`pick` | `drive` | `work` | `haul`). Khu mới cần thêm: entry `ZONE_FLOORS` + (nếu có lối vào) `CONNECTORS`/`paintPath` trong `src/ground/packs/scrapYard/worldGrounds.ts`, danh sách LOD trong `src/scenery/packs/scrapYard/pack.ts`, và một dòng trong `ZONE_PREVIEWS` ở `src/projects/scrapYard/tabs.tsx`; sàn khu dùng `paintBlob`/`paintPath` với `outside` đúng nền thật.
3. Đăng ký vào `src/content/index.ts`.
4. Unlock nhánh mới → khai `requires` (`Condition`) trên `BranchDef`/`ZoneDef`/`WorkerDef`/`UpgradeDef` trong content — hệ thống eval đã có sẵn ở `domain/conditions.ts`; mốc tiến trình mới thì thêm vào `src/content/milestones.ts` (thưởng viết bằng statKeys, không ghi save).
5. Chạy `npm run check` — golden balance test (`tests/golden.balance.test.ts`) sẽ nhắc nếu economy lệch khỏi baseline đã khóa (re-lock phải có chủ đích + ghi lý do).

- Tài nguyên/giá là `Decimal`; số lượng worker là `number`.
